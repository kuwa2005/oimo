Open Mimo Code — CLI Reference

$ oimo

oimo は、AI コーディングエージェント Open Mimo Code のコマンドラインインターフェースです。 ターミナル内の対話 UI（TUI）、非対話のワンショット実行、リモートサーバー運用、モデル・セッション・ プロバイダの管理など、すべての操作をこの 1 つのコマンドで行えます。

$ oimo # 対話 UI を起動（既定コマンド） $ oimo run "テストを実行して" # 非対話で 1 回だけ実行 $ oimo --help # 全コマンド・オプションの一覧

概要

コマンドは基本 oimo <コマンド> [引数..] [オプション..] の形式です。 引数を省略して oimo だけを実行すると、カレントディレクトリをプロジェクトとして 対話 UI（TUI）が起動します。オプション（-- で始まる指定）は、そのコマンドの 動作を細かく調整するために使います。

クイックスタート

$ oimo # 対話 UI を起動（最も一般的な使い方） $ oimo run "このリポジトリの README を要約して" $ oimo -c # 直前のセッションを継続 $ oimo -m openai/gpt-5.6 # モデルを指定して起動（provider/model 形式） $ oimo --tor # Tor SOCKS5 経由で通信を匿名化

詳しいヘルプはいつでも oimo --help（コマンド全体）または oimo <コマンド> --help（個別コマンド）で表示できます。 また、このマニュアル内では各オプションに「用途」として、いつ・何のために使うのかを補足しています。

グローバルオプション

oimo --help に表示される共通オプションです。既定コマンド（TUI）と serve / acp / attach は、このうちネットワーク関連の オプションを共有しています。

共通オプション

オプション説明
-h, --helpヘルプを表示コマンド名・オプション名を忘れたときにその場で確認するために使います。oimo run --help のように個別コマンドにも付けられます。
-v, --versionバージョンを表示今のバージョンを知るために使います。不具合報告やアップグレードの要否判断、oimo upgrade でどこまで上げるか確認する際に便利です。
--print-logsログを stderr に出力トラブルシューティング用です。ログファイルを開かなくても、起動中の oimo の内部ログをそのまま画面に出して原因を追えます。
--log-levelログレベル DEBUG / INFO / WARN / ERRORログの出力量を制御します。原因調査で詳細が見たいときは DEBUG、普段は WARN や ERROR に絞る、といった使い分けをします。
--pure外部プラグインなしで実行プラグインの影響を切り分けるためのモードです。「プラグインを入れてから挙動がおかしくなった」という場合に、これを付けて起動すると素の状態と比較できます。
--tor全通信を Tor SOCKS5 プロキシ経由にルーティング通信先に自分の IP アドレスを知られたくない場合に使います（匿名化）。ローカルに Tor デーモン（既定 socks5h://127.0.0.1:9050）を起動しておく必要があります。モデル API 呼び出しなど oimo の通信全体が対象です。
--log <file>TUI セッションの質問と要約を Markdown ファイルに追記作業の記録・振り返り用です。会話の全文ではなく、質問と最終的な要約だけが指定ファイルに追記されていくので、日報や議事録の材料として使えます。

ネットワークオプション（TUI / serve / acp 共通）

オプション説明既定値
--portリッスンポートサーバーとして公開するポートを固定したいときに指定します。既定は 0（自動で空きポートを選択）。ポートフォワードやファイアウォールの設定に合わせて固定します。0（自動）
--hostnameリッスンするホスト名0.0.0.0 にすると LAN 上の他のマシンからもアクセスできます（その場合 MIMOCODE_SERVER_PASSWORD による認証が必須）。既定の 127.0.0.1 はローカル専用です。127.0.0.1
--mdnsmDNS サービスディスカバリを有効化同じネットワーク内の他のマシンから、サーバーの存在を自動検出（Bonjour / Zeroconf 相当）できるようにします。有効にすると hostname が 0.0.0.0 になります。false
--mdns-domainmDNS 用のカスタムドメインmDNS で探すときの検索ドメインを変更したい場合に使います。複数サーバーをドメインで区別したいときなど。oimo.local
--corsCORS を許可する追加ドメイン（複数指定可）Web クライアントなど、別オリジンからサーバー API を呼び出す場合に許可ドメインを追加します。ブラウザからのアクセスを想定した開発時などに使います。[]
--no-auth非ループバックアドレスで認証なし起動を許可（危険）テストや信頼できるネットワーク内でのみ使う危険なオプションです。通常は非ループバックで起動する場合、MIMOCODE_SERVER_PASSWORD の設定が必須ですが、これを付けると認証なしで公開できます。false

TUI 起動オプション

オプション説明
-m, --model使用するモデル provider/model 形式デフォルトモデル以外を使いたいときに指定します。例: oimo -m openai/gpt-5.6。選択できるモデルは oimo models で確認できます。
-c, --continue直前のセッションを継続前回の会話の続きから再開したいときに使います。中断した作業の再開が主な用途です。
-s, --sessionセッション ID を指定して継続特定の過去セッションを選んで再開したいときに使います。oimo session list で ID を確認できます。
--fork継続時にセッションをフォーク （--continue または --session と併用）元のセッションを変えずに、分岐したコピー上で別の進め方を試したいときに使います。「やり直し」「別アプローチを試す」に適しています。
--prompt使用するプロンプト最初の入力をコマンドラインから指定したいときに使います。標準入力（パイプ）で渡すこともできます。例: oimo --prompt "README を作成して"。
--agent使用するエージェントエージェント（build / plan / compose など）を選びたいときに指定します。TUI では起動後も /agent コマンドで切り替えられます。
--never-asknever-ask モードで開始（権限系は対象外）AI 側からの確認質問を省略して先へ進めるモードです。ただし危険な権限（bash の実行など）は対象外で、通常どおり確認されます。実行中は /never-ask でオン/オフを切り替えられます。
--autonomy, --seSE 型自律実行モード（詳細は「ワークフロー例」3 参照）「ソフトウェアエンジニア型の自律実行」をしたいときに使います。要件をヒアリングしてロックした後、書類証跡（要件・テスト基準・検証結果）を残しながらノンストップで実装を進めます。compose エージェントを暗黙指定し、安全な権限は自動承認します。
--trustワークスペース信頼確認をスキップ起動時に毎回出る「このディレクトリを信頼しますか?」をスキップして即作業に入りたいときに使います。自分が管理するディレクトリで便利です。
--dangerously-skip-permissions明示的に拒否されていない権限を自動承認（危険）CI や自動実行など、確認を挟まず進めたい場合の危険なオプションです。ファイル削除やコマンド実行の都度確認が出なくなるため、内容を把握した上で使います。
--auto自動承認 + ワークスペース信頼確認もスキップ（危険）--dangerously-skip-permissions と同等の自動承認に加え、ワークスペースの信頼確認もスキップします。完全に自動で走らせたいとき（CI など）のためのショートカットです。

oimo [project]

既定コマンド

対話 UI（TUI）を起動します。ターミナル上でエージェントと会話しながら作業する、最も基本的な使い方です。

$ oimo [project] [options]
引数説明
project作業を開始するディレクトリのパス（省略時はカレントディレクトリ）複数のプロジェクトを行き来する場合、対象ディレクトリを明示します。例: oimo ~/work/app-a。

例

# カレントディレクトリで対話 UI を起動
oimo

# 指定ディレクトリをプロジェクトとして起動
oimo ~/my-project

# モデルを指定して起動
oimo -m openai/gpt-5.6

# 直前のセッションを続行
oimo -c

# 特定セッションをフォークして続行
oimo -s ses_abc123 --fork

# SE 型自律実行モード（要件ロック → 証跡付き自動実装）
oimo --se

# Tor 経由で匿名化（--auto と併用で信頼確認もスキップ）
oimo --tor --auto
起動時にワークスペースの信頼確認が行われます。--trust / --auto / --dangerously-skip-permissions でスキップできます。

oimo run [message..]

メッセージを渡して非対話で 1 回だけ実行します。対話 UI を開かずに「この指示を 1 回処理する」用途です。スクリプト・CI・パイプ処理と組み合わせやすいのが特徴です。

$ oimo run [message..] [options]
引数説明
message..送信するメッセージ（複数指定すると連結）「何をやるか」をその場で渡します。複数指定した場合はスペース区切りで連結されます。-- 以降に書いた単語もメッセージ末尾に追加されます。
オプション説明
--command実行するコマンド（引数は message で渡す）定型の指示を変数化して使い回したいときに使います。例: oimo run --command "テストを実行して" --dir packages/opencode。
-c, --continue直前のセッションを継続前回の run の続きをやりたいときに使います。文脈を引き継いで続行できます。
-s, --sessionセッション ID を指定して継続特定の過去セッションを選んで続きを実行したいときに使います。
--fork継続前にセッションをフォーク （--continue / --session 必須）元のセッションを汚さず、分岐したコピーで試行したいときに使います。
--shareセッションを共有（共有 URL を生成）実行結果を共有 URL として公開し、レビュワーや別の開発者に見せたいときに使います。他人が oimo import で取り込んで続きを引き継ぐこともできます。
-m, --model使用するモデル provider/model 形式この 1 回だけ別のモデルで実行したいときに使います。
--agent使用するエージェントplan（調査・設計）で先に検討させてから build で実装する、といったエージェントの使い分けをしたいときに使います。
--format出力形式 default（整形済み）/ json（生の JSON イベント）json は tool_use / step_start / step_finish / text などのイベントが NDJSON で流れるため、jq などで機械的に処理したいときに使います。
-f, --fileメッセージに添付するファイル（複数指定可）特定のファイルを対象にレビューや修正を依頼するときに使います。例: oimo run -f src/main.ts "このファイルをレビューして"。
--titleセッションのタイトルセッション一覧で見分けやすいように名前を付けておきたいときに使います。省略時はプロンプトの先頭から自動生成されます。
--attach <url>実行中の oimo サーバーに接続して実行 例: http://localhost:4096重い処理をリモートの oimo serve で実行したいときに使います。ローカルでは接続するだけなので、マシンが変わっても同じ環境で実行できます。
-p, --passwordBasic 認証パスワード （既定: MIMOCODE_SERVER_PASSWORD）--attach で接続するサーバーがパスワード認証付きの場合に使います。環境変数でも設定できます。
--dir <path>実行ディレクトリ別のディレクトリを対象に実行したいときに使います。--attach 時は、そのパスはリモートサーバー上のパスとして扱われます。
--portローカルサーバーのポート内部で起動するローカルサーバーのポートを固定したいときに使います。省略時はランダムです。
--variantモデルバリアント（reasoning effort 等）モデルごとの「考える深さ」を指定したいときに使います。プロバイダ固有の値（high / max / minimal など）を渡します。複雑なタスクは high、手早く済ませたいときは minimal、といった使い分けです。
--thinkingthinking ブロックを表示モデルの思考過程（回答に至るまでの推論）を画面に出したいときに使います。結果が腑に落ちないときの確認に有効です。
--role注入メッセージのロール user / assistantassistant を指定すると、渡したテキストが「AI がすでに言ったこと」として注入され、その続きの生成を促します。会話を途中から再現・誘導したい特殊な用途です。
--auto明示的に拒否されていない権限を自動承認（危険）CI や夜間実行など、対話なしで完結させたいときに使います。コマンド実行の都度の確認がなくなるため、対象を限定して使います。

例

# ワンショット実行
oimo run "このリポジトリのテストを実行して結果を教えて"

# --command でコマンドを指定
oimo run --command "bun test" --dir packages/opencode

# 標準入力からメッセージを渡す
cat spec.txt | oimo run "この仕様を実装して"

# ファイルを添付してレビューを依頼
oimo run -f src/main.ts -f src/util.ts "これら 2 ファイルのレビューをして"

# 直前のセッションをフォークして続行
oimo run -c --fork "ここまでの続きをやって"

# プロセスイベントを JSON で受信
oimo run --format json "3 ファイルに分割して"

# 実行中のサーバーへ接続して実行
oimo run --attach http://127.0.0.1:4096 "リモートで実行して"

oimo attach <url>

実行中の oimo サーバーに接続し、そのサーバーに対して対話 UI（TUI）を起動します。表示はローカル、処理はリモートという使い方のためのコマンドです。

$ oimo attach <url> [options]
引数説明
url接続先サーバーの URL 例: http://localhost:4096SSH ポートフォワードでつないだリモートのサーバーや、LAN 上の oimo serve を指定します。
オプション説明
--dir作業ディレクトリローカルとリモートでディレクトリ構成が違う場合に、リモート側で作業するパスを指定します。ローカルに存在する場合はローカルで作業、無ければリモート上のパスとして送られます。
-c, --continue直前のセッションを継続サーバー上の直前セッションを続けたいときに使います。
-s, --sessionセッション ID を指定して継続サーバー上の特定セッションを選んで再開したいときに使います。
--fork継続時にセッションをフォーク （--continue / --session と併用）元を残して別ブランチで進めたいときに使います。
-p, --passwordBasic 認証パスワード （既定: MIMOCODE_SERVER_PASSWORD）接続先サーバーがパスワード認証付きの場合に使います。

例

# ローカルで起動したサーバーに接続
oimo serve --port 4096 &
oimo attach http://127.0.0.1:4096

# SSH ポートフォワードでリモートのサーバーに接続
ssh -N -L 4096:127.0.0.1:4096 user@remote-host
oimo attach http://127.0.0.1:4096
TUI が遅くなる環境（SSH 直打ちなど）では、表示をローカル、実行をリモートに分離すると快適です。

oimo serve

ヘッドレス（UI なし）の oimo サーバーを起動します。TUI を持たないマシン（リモートサーバー・CI 環境）で「処理する側」を立て、別のマシンから接続するためのコマンドです。

$ oimo serve [options]

例

# ポート 4096 でサーバーを起動
oimo serve --port 4096

# パスワード付きで起動（非ループバックへ公開する場合）
MIMOCODE_SERVER_PASSWORD=secret oimo serve --hostname 0.0.0.0 --port 4096

# mDNS でネットワーク内から発見可能にする
oimo serve --mdns --port 4096
非ループバックアドレス（0.0.0.0 等）にバインドするには MIMOCODE_SERVER_PASSWORD の設定（または危険な --no-auth）が必要です。 認証ユーザー名は MIMOCODE_SERVER_USERNAME（既定 oimo）。

oimo acp

ACP（Agent Client Protocol）サーバーを起動します。ACP 対応のホスト（IDE やエージェントクライアント）から oimo をエージェントとして使うためのコマンドです。

ACP とは — エージェントとクライアントを標準入出力（NDJSON ストリーム）で接続するためのプロトコルです。 oimo acp は oimo をヘッドレスサーバーとして起動し、そのやり取りを ACP の規格に変換します。 そのため、ACP を話せるクライアントからは oimo を「差し替え可能なエージェント」として組み込めます。

$ oimo acp [network-options] [--cwd <dir>]
オプション説明
--cwd作業ディレクトリACP クライアントから渡される作業場所を上書きしたい場合に使います。既定はカレントディレクトリです。（既定: カレント）
--port / --hostname / --mdns / --mdns-domain / --cors / --no-authネットワークオプション内部で起動するサーバーの公開方法を制御します。前掲の「ネットワークオプション」参照。

例

# ACP サーバーをポート 4096 で起動
oimo acp --port 4096

# 特定ディレクトリを作業場所にして起動
oimo acp --cwd /path/to/project

oimo session <list|delete|import-claude>

セッション（会話の履歴）の管理を行います。過去の作業の一覧・削除、他ツールからの取り込みに使います。

$ oimo session list [options]
$ oimo session delete <sessionID>
$ oimo session import-claude [--force]

サブコマンド

サブコマンド説明
listセッションの一覧を表示どのセッションを再開するか探すための入口です。ターミナルでは一覧が対話ピッカーになり、矢印キー + Enter でそのセッションを TUI でそのまま再開できます。スクリプト用に --format json も使えます。
delete <sessionID>セッションを削除不要になった履歴を消してデータを整理したいときに使います。ID は session list で確認します。
import-claudeClaude Code のセッションを oimo に取り込みClaude Code（~/.claude/projects）で過去にやった作業の履歴を oimo に引き継ぎ、続きの作業を始めたいときに使います。
オプション説明
-n, --max-count直近 N 件に制限 （list）セッションが大量にあって直近分だけ見たいときに使います。
--format出力形式 table / json（既定: table）json は jq などで処理しやすいため、スクリプト連携時に使います。
--forcemtime キャッシュを無視して全セッションを再同期 （import-claude）前回からの差分だけではなく全部を取り込み直したいときに使います。取り込み漏れが疑われる場合など。

例

# 直近 20 件を一覧
oimo session list -n 20

# JSON で取得（スクリプト処理用）
oimo session list --format json

# セッションを削除
oimo session delete ses_abc123

# Claude Code のセッションを取り込む
oimo session import-claude
oimo session import-claude --force

oimo models [provider]

利用可能なモデルの一覧を表示します。各モデルの解決済みウィンドウ（コンテキスト上限）と、どのトークン数で圧縮されるかも表示されるため、「このモデルは実際どれだけのコンテキストが使えるか」の確認にも使えます。

$ oimo models [provider] [options]
オプション説明

oimo completion [shell]

シェル補完スクリプトを生成します。

これは何のためにあるか — シェル補完とは、ターミナルで oimo に続けて Tab キーを押すと、使えるコマンド名・サブコマンド・オプションの候補が自動で表示される機能です。 oimo はコマンドと -- オプションが非常に多いため、これを設定しておくと 「オプション名を覚えていなくても Tab で候補を見ながら入力できる」「タイプ量が減る」という利点があります。 生成したスクリプトは一度シェルの設定に読み込ませれば、以後のセッションで毎回有効になります。

$ oimo completion [bash|zsh|fish]
引数説明
[shell]補完スクリプトを生成する対象シェル bash / zsh / fish（省略時は現在のシェルを検出）使っているシェルに合わせて選びます。シェルごとに読み込み方（source / fpath など）が異なるため、生成後にシェルの設定ファイルへ反映する必要があります。

例

# bash: 出力を設定ファイルに追記
oimo completion bash > ~/.oimo/completion.bash
echo "source ~/.oimo/completion.bash" >> ~/.bashrc
# 反映後: oimo <Tab> でコマンド候補、oimo run --<Tab> でオプション候補が表示される

# zsh
oimo completion zsh > "${fpath[1]}/_oimo"
# 補完を有効化（未設定の場合）: 通常は compinit を ~/.zshrc に記述

# fish
oimo completion fish > ~/.config/fish/completions/oimo.fish
反映方法はお使いのシェルによって異なります。上記は一般的な例です。設定後はターミナルを開き直すか source ~/.bashrc（bash）などで反映します。

MIMOCODE_DISABLE_COMPOSE_SKILLStrue で compose エージェント内部のスキルを無効化
MIMOCODE_DISABLE_SLASH_SKILLStrue でスキルを TUI の / オートコンプリートから非表示（無効化はしない）
GH_REPOアップグレード取得元リポジトリ （既定: kuwa2005/oimo）
MIMOCODE_INSTALL_SCRIPT_URLインストーラースクリプトの URL を上書き
MIMOCODE_UNINSTALL_DIRアンインストール対象ディレクトリ （既定: ~/.oimo/bin）
oimo github run はワークフロー実行用のため、MODEL / GITHUB_RUN_ID / PROMPT / MENTIONS / GITHUB_TOKEN などの環境変数を読みます。詳細は oimo github run --help を確認してください。

スキル（インストール時に同梱されるもの）

スキルとは、特定の作業（PDF 処理、調査、設計、自動リファクタリングなど）の手順を SKILL.md にまとめた「作業手順書」です。エージェントがタスクに合うスキルを 見つけると skill ツールで読み込んで、その手順に従って作業します。

oimo を標準インストーラーで導入すると、このスキルはバイナリに同梱されており、追加の インストール手順は不要です。初回起動時に oimo が組み込みスキル（builtin）と compose スキルを自動でデータディレクトリへ展開します（バージョン管理されたマーカー付き）。 つまり「標準インストーラーでインストールされるスキル」＝ この同梱スキル一式ということになります。

$ curl -fsSL https://raw.githubusercontent.com/kuwa2005/oimo/main/install | bash # macOS / Linux $ irm https://raw.githubusercontent.com/kuwa2005/oimo/main/install.ps1 | iex # Windows PowerShell $ oimo debug skill # 読み込まれている全スキルを確認

スキルの上書きと無効化

  • 上書き: プロジェクトの .oimo/skills/<name>/SKILL.md、または個人スキル ディレクトリ（~/.claude/skills/、~/.opencode/skills/ など）に同じ name の SKILL.md を置くと、組み込みスキルを上書きできます。設定の skills.paths / skills.urls で追加フォルダや外部 URL からも読み込めます。
  • 確認: TUI で /skills、または oimo debug skill で一覧表示。
  • 無効化: MIMOCODE_DISABLE_BUILTIN_SKILLS / MIMOCODE_DISABLE_OFFICIAL_SKILLS / MIMOCODE_DISABLE_COMPOSE_SKILLS を 参照（前掲「環境変数」）。

ワークフロー例

1. リモートホストでサーバー運用し、ローカルから接続

TUI が遅くなる環境（SSH 直打ちなど）では、表示をローカルに、実行をリモートに分離できます。

# リモートホスト
oimo serve --port 4096

# ローカルホスト: SSH ポートフォワードを作成
ssh -N -L 4096:127.0.0.1:4096 user@remote-host

# ローカルホスト: 別のターミナルから接続
oimo attach http://127.0.0.1:4096

# 非対話で実行する場合
oimo run --attach http://127.0.0.1:4096 "ビルドを直して"

2. Tor による匿名利用

# ローカル Tor デーモン（ポート 9050）を起動してから
oimo --tor
oimo run --tor "リポジトリを調査して"

3. SE 型自律実行（要件ロック → 証跡付き自動開発）

--se（別名 --autonomy）は「優秀なソフトウェアエンジニアが曖昧な依頼を受けたら どう進めるか」を AI に強制するモードです。compose エージェントを暗黙指定し、要件をヒアリングして 「要件ロック」するまで実装を始めず、その後は証跡（書類）を残しながらノンストップで実装・テスト・検証を 完遂します。権限の自動承認（安全なもの）も同時に有効になるため、--auto は不要です。 

# 起動
oimo --se ~/my-project

# 環境変数でも同じ
MIMOCODE_AUTONOMY=1 oimo ~/my-project

Phase A — ヒアリング（要件ロックまで）: 実装コードは一切書かず、以下を進めます。

  • 文脈と隠れた要望を調査し、顧客（ユーザー）が考えていない前提を質問で引き出す
  • 確認はすべて question ツール（compose:ask）経由。散文だけで質問してターンを終えない
  • 各質問をヒアリングログに記録（なぜ聞いたか・背景・回答結果）
  • 複雑さに応じた要件・機能仕様を作成。テスト基準は仕様の中に含める
  • 最後にヘッダーがちょうど Requirements Lock の質問を投げ、Approved / Changes needed で確定させる

Phase B — 実行（ノンストップ）: ロック後は以下を止まらずに完了まで進めます。

  • 実装 → テスト仕様で定義したテストプログラムを実際に作成・実行 → pass/fail を reports/ に記録。テストは必須成果物です（index.html 1 枚でも、コアロジックを分離して実行する）
  • 実装フェーズでは compose:brainstorm → compose:plan → compose:tdd → compose:verify → compose:review → compose:report の順でスキルを使う
  • 独立した judge モデルがトランスクリプト（履歴）だけを読んで「完了」または「不可能」を判定するまで継続

書類証跡: このモードの成果物はコードだけでなく書類です。後から読んだ人が 意思決定の理由を書類だけで追えることが要件になります（既定の保存先 docs/compose/）。

docs/compose/
├── specs/     # 要件・機能仕様・テスト仕様
├── plans/     # 実装計画
└── reports/   # テスト実行結果・検証エビデンス・最終レポート

停止条件と予算: judge の判定に加え、以下の上限に達すると停止します （停止理由: completed / impossible / cancelled / budget_turns / budget_duration / budget_cost / judge_failed）。既定値は oimo.json の autonomy ブロックで変更できます。

設定項目既定値説明
enabledfalse自律モード有効化（--se フラグまたは MIMOCODE_AUTONOMY=1 と同等）
hearing_firsttrue要件ロックまで実装しない（false なら即 execute フェーズ）
docs_evidencetrue停止条件に書類証跡を含める
max_turns50judge 主導の再入場回数の上限
max_duration_ms7200000（2 時間）1 タスクの実行時間の上限
max_cost_usd101 タスクの累計コスト上限（各モデル呼び出し前にチェック）
judge_max_retries2judge 判定失敗時のリトライ回数（超えると judge_failed で停止）
--se は TUI 起動オプションです。oimo run にはありません。 実行中に止めたい場合は通常どおり Ctrl+C などで中断（cancelled）できます。 権限の強制確認（forced-ask）は自動承認されないため、重要な操作は引き続き確認が入ります。

4. セッションの共有と引き継ぎ

# 実行結果を共有 URL にする
oimo run --share "調査結果をまとめて"

# 共有 URL を取り込んで継続
oimo import https://opncd.ai/share/abc123
oimo -s <取り込まれたセッションID>

# 対話で追加（名前・種別・コマンド/URL を入力）
