## 3. 要件定義

### 3.1 機能要件（FR）

| ID | 要件 | 受入条件 |
|---|---|---|
| FR-01 | 自律開発・AI駆動開発に必要な能力を 10 領域で整理する | 各領域に定義・構成要素・成熟度・根拠がある |
| FR-02 | oimo の現状をコード/テスト/DB で評価する | 各評価に file path または集計クエリがある |
| FR-03 | 既存 BLOG-001〜011 と 4 brief を重複排除して統合する | 全 11 ID の去就（統合/維持/廃止）が表にある |
| FR-04 | 改善項目を `Improvement Score` で優先順位付けする | 頻度・時間損失・影響度・再発可能性の4因子と算出根拠がある |
| FR-05 | ハード進化項目を 9 セクション形式で全件収録する | 各 brief に 9 見出しが揃う |
| FR-06 | Now/Next/Later のロードマップと受入条件を与える | 各項目に完了判定がある |
| FR-07 | 機械検証可能なテスト仕様を定義し、実行記録を残す | T1〜T10 の合否が `reports/` にある |
| FR-08 | BACKLOG.md / INDEX.md の状態矛盾を解消する | 更新後の状態が本文と一致する |

### 3.2 非機能要件（NFR）

| ID | 要件 |
|---|---|
| NFR-01 | 日本語で記述する（ユーザーの言語に一致） |
| NFR-02 | 既存 docs / backlog / brief を破壊しない（追記・状態更新のみ） |
| NFR-03 | 秘密情報を含めない（API キー、トークン、接続文字列、秘密鍵） |
| NFR-04 | 推測と事実を明示的に区別する（「推測」ラベル） |
| NFR-05 | 数値には測定窓（14日/30日/180日）と出典を付す |
| NFR-06 | 文書内リンクは相対パスで解決できる |
| NFR-07 | 後続 AI が単独で着手できる粒度（対象ファイル・受け入れ条件・検証コマンド） |

### 3.3 スコープ外

- 製品ソースの変更、commit / push / merge。
- 新しい skill / hook の実装（提案と受入条件まで）。
- `docs/evolve/*` の全面書き換え（矛盾点の指摘と最小修正に留める）。
- macOS / Windows での実機検証。
